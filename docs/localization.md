# DMR — Localization

## 1. Базовые правила

- Default locale: `de`. Первая полностью реализованная локаль — `de`
  (guest и staff/admin UI).
- Будущие локали (`en`, `ru`, др.) добавляются без изменения основной
  схемы данных — потому что translation-модель (см. `data-model.md` §3)
  уже расширяема с первого дня.
- Все пользовательские строки — в message catalogs (next-intl), никаких
  строк, захардкоженных в компонентах.
- Отсутствующий перевод безопасно откатывается на `de` (fallback), не
  падает и не показывает пустоту.

## 2. Locale routing

- Locale routing настроен с начала (next-intl), даже если публично
  включена только `de`.
- QR-код на столе ведёт на **нейтральный к языку** URL (без
  locale-префикса) — `/t/<opaqueToken>`. Этот route:
  1. смотрит сохранённый язык участника (cookie/session), если есть —
     редиректит на него;
  2. иначе — редиректит на `de` (текущий default).
- Staff/admin UI первой версии — тоже `de` (единая консистентная среда
  для персонала).

## 3. Translation-модель (напоминание, детали в data-model.md)

Каждая переводимая сущность меню имеет отдельную `*Translation`-таблицу
(`locale`, поля перевода), а не колонки `nameDe/nameEn/nameRu` на самой
сущности. Это обязательное архитектурное решение — нерасширяемые
locale-колонки прямо запрещены ТЗ и наблюдались как антипаттерн в
референс-проекте (`RestaurantMenuItem.nameDe/nameEn`).

## 4. Форматирование

- Валюта, числа, даты — через `Intl` API с текущей locale участника/
  сотрудника (аналог `Intl.NumberFormat` уже используется в референсе
  для цен ресторана — паттерн переиспользуем).
- Часовой пояс операционных правил (открытие/закрытие, отчёты) — Europe/
  Berlin, как в референс-проекте для бронирований.

## 5. Что переиспользуемо из референса

`next-intl` уже используется в Waldschlösschen (`de`/`en`, locale prefix
всегда, `src/proxy.ts` защищает `/admin`) — подтверждает выбор
технологии для DMR. Сам message-каталог и структура `src/data/messages`
не переносятся напрямую (другой домен контента), но паттерн организации
(`messages/de.json`, ключи по секциям) можно взять за основу для
`src/domains/localization/messages/`.

## 6. Тестовое покрытие

Accessibility/locale smoke: страница меню и staff-экраны рендерятся на
`de` без ключей-заглушек (`missing translation`). При добавлении `en` —
тест на fallback (намеренно неполный перевод одной позиции меню
показывает `de`-текст, не пустую строку и не ключ).
